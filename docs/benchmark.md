# Benchmark

Synthetic scenarios with planted problems and look-alike clean cases are sent through the same pipelines the apps run. The alerts are matched to the planted labels and counted. The numbers describe this synthetic mix; they are reported, never used as a pass mark.

Seed `2026`, `200` scenarios per app.

## Reproduce

```
python scripts/benchmark.py
python scripts/benchmark.py --check
python scripts/benchmark.py --export-scenarios DIR
```

The first command writes `data/benchmark/results.json` and this file. `--check` runs the benchmark again and compares the bytes with the committed files without writing. `--export-scenarios` writes every scenario with its labels for inspection.

## Matching rule

Within one scenario, alerts are visited in ascending order of (natural order of the first source_ref, type, source_refs). An alert is a true positive when a still-unmatched label of the same type exists whose rows share at least one source_ref with the alert; if several labels qualify, the one with the largest overlap wins, ties by label id. A matched label is consumed and cannot match a second alert. An alert that matches no label is a false positive; a label never matched is a false negative. Context rows never match.

## Limits

- All data is synthetic and comes from `scripts/generate_benchmark.py`; real statements and invoices are messier.
- The labels were written by the project team that also wrote the detector requirements; a pattern nobody thought of is neither planted nor labelled.
- Boundary values follow our reading of the requirements; where a requirement is ambiguous the benchmark follows the documented behaviour.
- The shares of clean and planted scenarios and the number of cases per scenario are our choice; precision and recall describe this mix, not another one.
- Only plain-dialect CSV is benchmarked. The Norma bank-statement format, Facturae, European CSV and the CPI context are covered by other tests.
- VAT amounts and totals in the generator use the same money helpers as the detectors; rounding cases therefore also use hand-checked literal values.
- Payments dated after the matching window of the reconciliation are not benchmarked.
