New scripts/record_live_run.py, run with the kit's own Python: for the three CSV demos, every alert card once, plus the three trick questions of ledger_kit/live_guard.py on the first critical card of each app (the same scope as the 11 Nov demo file; say so in the docstring). It calls the model exactly the way the apps do (explain_with_meta with the real client, the same template, row columns, CPI context and question), with the endpoint, key, model and timeout read from the same environment variables as the apps (OPENAI_BASE_URL, OPENAI_API_KEY, LEDGER_KIT_LLM_MODEL, LEDGER_KIT_LLM_TIMEOUT), temperature 0 and no retries as today. For each record it writes the raw answer exactly as received, the seconds, and observed_source, observed_rejected, plus two new fields: observed_reason (the rejection reason, empty when accepted) and observed_calcs (the kit's calculations, empty when none). Arguments: --out (required; the script refuses to overwrite an existing file), --machine (free text written into machine), --tag, and --dry-run, which lists every record it would ask (app, id, title, question) and calls nothing. It prints one line per record while it runs, and writes the file only at the end, so a failed run leaves nothing half-written. Record ids follow the 11 Nov file's style (Z, P, V plus a two-digit number; questions as in that file).
