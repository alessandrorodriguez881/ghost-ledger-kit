Session 20a, new spec cli-hooks: hooks that really run in the Kiro CLI build of this repo.

Context. The three files in .kiro/hooks/ (*.kiro.hook) are IDE hooks. This repo is built through Kiro CLI V3 (kiro_prompts/run_kiro.ps1 uses --v3 --mode spec --trust-workspace), which does not read them, so they never ran. Kiro CLI V3 does run standalone workspace hooks from .kiro/hooks/*.json (format version v1, documented at kiro.dev/docs/hooks). I checked it today in a throwaway folder with --no-interactive --v3 --trust-workspace: SessionStart, UserPromptSubmit, PostToolUse (matcher write) and Stop all fired. Facts from that check, to rely on:
- The command runs in the workspace root and gets one JSON object on stdin. Keys seen: session_id, hook_event_name, cwd. For PostToolUse also tool_name (fs_write was seen), tool_input (for fs_write: path, an absolute path, and text) and tool_response (a string). Other write tools may use other tool_input keys: read path, else file_path, else treat it as no path.
- Exit code 0: stdout is added to the agent context. Any other exit code: stderr is sent to the agent as a hook error. The timeout field is in seconds (default 60).
- The bare command python worked on this machine.

Goal. You, Kiro, have no shell in this build. These hooks give you lint feedback right after each write and the tests of what you touched when you stop, and they leave a log in the repo that proves they ran.

Do, in order:
1. Spec first: .kiro/specs/cli-hooks/requirements.md (EARS, ids REQ-CH-nn, acceptance examples AE-CH-nn with the stdin payloads written as tables of keys and values, not raw JSON), design.md and tasks.md (test-first tasks CH1, CH2 and so on, the last one a record of Kiro calls for the reviewer to fill in).
2. scripts/kiro_hooks.py, standard library only, run as python scripts/kiro_hooks.py EVENT with EVENT post-write or stop.
   a. post-write: read the stdin JSON and take the written path from tool_input. Record it (repo-relative, forward slashes) in a per-session state file under the system temp folder (tempfile.gettempdir(), subfolder ghost-ledger-hooks, file named after a safe form of session_id), never inside the repo. If the path is a .py file inside the repo, run ruff check and ruff format --check on that one file with the repo interpreter (.venv/Scripts/python.exe on Windows, .venv/bin/python elsewhere, else sys.executable) as python -m ruff, time limit 30 s. Pass: print one line, ruff OK on FILE, and exit 0. Fail: print the ruff findings (at most 40 lines) to stderr and exit 1, so the agent sees them and can fix the file. Not a .py file, outside the repo, or no path: exit 0 with a one-line skip message.
   b. stop: read the stdin JSON and the session state. Choose test targets from the touched files: a file under apps/NAME/ adds apps/NAME/tests; a file under ledger_kit/, scripts/ or tests/ adds tests; any other file (docs, .kiro, data, README) adds nothing; each target once, in a stable order. Run ruff check . and then, only if there are targets, python -m pytest -q -x -p no:cacheprovider TARGETS with a time limit of 540 s. Always exit 0, because a failing Stop hook must not keep the agent looping. Print a short summary to stdout: the ruff result, the last summary line pytest prints (the passed and failed counts), and the first failing test id if any. Remove the session state file at the end.
   c. Log: every post-write and stop run appends one JSON line to data/hook_runs/hook_log.jsonl with exactly the keys time (local clock, ISO format, seconds), event, session (the session_id), file (repo-relative, post-write only, else null), checks (list of the check names run), result (pass, fail, skipped or error), detail (at most 200 characters: the pytest summary line, the ruff error codes, or the skip reason) and seconds (duration, one decimal). Never write an absolute path, a user name, the prompt text or file contents into the log, stdout or stderr: make every path repo-relative, and write outside-repo for a path outside the repo.
   d. Robustness: bad or empty stdin, missing ruff, missing .venv, a timeout or any unexpected exception is logged with result error and ends with exit 0 and a one-line message. The only nonzero exit is a real ruff finding in post-write. Keep it testable: the logic lives in functions that take the payload, the repo root, a clock and a command runner, and main() is a thin wrapper.
3. .kiro/hooks/review-gate.json, format version v1, with two hooks: lint-after-write (trigger PostToolUse, matcher write, action type command, command python scripts/kiro_hooks.py post-write, timeout 60) and tests-on-stop (trigger Stop, action type command, command python scripts/kiro_hooks.py stop, timeout 600). Write it after scripts/kiro_hooks.py exists. Keep the three .kiro.hook files unchanged for IDE users.
4. data/hook_runs/README.md: what the log is, its keys, that the hooks write it during real Kiro calls and nobody edits it by hand. Do not create hook_log.jsonl yourself. In .gitignore add !data/hook_runs/ and !data/hook_runs/** next to the data/live_runs lines, with a one-line comment.
5. Tests first, tests/test_kiro_hooks.py. Build the payloads from the facts above with a fake repo root from tmp_path (never a real user path), a fake command runner and a fixed clock; no real ruff or pytest call. Cover: an fs_write payload on a .py file that passes, and one that fails (exit 1, findings on stderr); a .md file is skipped; a path outside the repo is logged as outside-repo; a payload with no path; bad JSON on stdin; a runner timeout gives result error and exit 0; stop with no touched files skips pytest; stop target selection for files under apps/NAME, ledger_kit, scripts and tests, each target once; stop exits 0 even when pytest fails; the state file is removed after stop; every log line has exactly the keys of step 2c and no absolute path; review-gate.json is valid JSON with version v1 and the two hooks exactly as in step 3; the script imports only standard-library modules.
6. In .kiro/steering/update-kiro-usage.md, change only the hooks line so it lists .kiro/hooks/*.json (CLI and IDE) and .kiro/hooks/*.kiro.hook (IDE only). Do not touch README.md in this session.

Change nothing else. Environment: Windows. You cannot run commands. When done, list the files you changed.
