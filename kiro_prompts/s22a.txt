Session 22a, new spec app-signatures: each app gets its own visual signature on every alert card, drawn only from the cited rows.

Context. A fresh jury found that the three apps look the same below their mastheads: every alert card is title, detector line, text, badge, refs as inline code and two expanders (Design 6 of 10; Zombie and Vampire even read the same kind of statement). The demo has 19 Zombie alerts (13 zs.recurring_charge, 2 zs.duplicate_subscription, 2 zs.price_increase, 1 zs.charges_after_cancellation with cancellation_date in its data, 1 zs.free_trial_to_paid), 9 Phantom alerts (pi.duplicate_invoice 3, pi.iban_change 3, pi.reconciliation 2, pi.vat_error 1) and 6 Vampire alerts (vf.recurring_fee 3, vf.fee_increase, vf.fee_summary, vf.overdraft_cost). The promise of the kit is that every figure on screen comes from a cited row, so the signatures must keep it.

Do, in order:

1. Spec first: .kiro/specs/app-signatures/requirements.md (EARS, ids REQ-AS-nn, acceptance examples AE-AS-nn), design.md and tasks.md (test-first tasks AS1, AS2 and so on, the last one a record of Kiro calls for the reviewer to fill in).

2. New pure module ledger_kit/ui/signatures.py (no Streamlit import), returning escaped HTML or inline SVG strings, colours from the Accent of each app in ledger_kit/ui/theme.py:
- refs_chips_html(refs): one chip per source ref, class gl-ref-chip, text file · row N for a ref of the form file:N (title attribute: the full ref), the raw ref otherwise. Every app replaces the inline-code refs after its Source refs: label with these chips; keep the label text Source refs:.
- heartbeat_svg for Zombie: one dot per cited row on a time line (x by date, from the first to the last cited date), the line drawn like a slow pulse. When the alert data has a cancellation_date, a small tombstone mark stands at that date with the word cancelled, and the dots after it are drawn brighter: the zombie charges. Visible text: only the first and last cited dates and, when present, the cancellation date. Each dot has an SVG title with the row's date and amount exactly as the Source rows expander shows them.
- bites_svg for Vampire: one bar per cited fee row on a time line, height proportional to the amount, drawn as fang-shaped bites. No sums or other computed figures anywhere: visible text only the first and last cited dates; each bar has an SVG title with that row's date and amount as the expander shows them. It must stay readable with the 45 rows of vf.fee_summary.
- lantern_html for Phantom: a compact table of the cited rows where the fields the detector compares are lit (class gl-lit, a soft lantern glow in the Phantom colour) and the other cells are dimmed. Pick the compared fields per detector by reading each detector module in apps/phantom_invoices/detectors, and write them as one mapping from detector id to column names in apps/phantom_invoices (not in ledger_kit); when a detector is not in the mapping, light the columns whose values differ between the cited rows. Values must be formatted exactly as the card's Source rows expander formats them, so an IBAN stays masked as it is there. The table scrolls sideways inside its own box on a narrow screen.
- Every SVG has role img and an aria-label in words with no figures (for example: Charges of this alert over time, one dot per cited row). Each signature sits in a div of class gl-signature, with one short caption line without figures: Each mark is one cited row. The CSS goes in ledger_kit/ui/theme.py next to the card styles, and works on the dark theme at 1400 and 800 px wide.

3. In each app (apps/zombie_subscriptions/app.py, apps/phantom_invoices/app.py, apps/vampire_fees/app.py) draw the signature inside every alert card, right after the guard badge and before the Source refs line, from the same cited rows the Source rows expander shows. Change nothing else on the pages.

4. Tests first, in new files only:
- tests/test_signatures.py: the chips (escaping, the file · row N form, a ref without a row); heartbeat dots equal the cited rows; the tombstone appears only with a cancellation_date and the dots after it are marked; bites bars equal the cited rows, also for 45 rows; the lantern lights the mapped columns and falls back to the differing ones; no full IBAN in the lantern, only the masked form of the expander.
- The honesty test, over every demo alert of the three apps (build them with tests/judge_path_support.py cases_of): take the text of the signature (the visible text and the SVG titles, without tags or attributes) and run ledger_kit.explainer.check_figures on it with the alert, its rows and its row columns; it must pass for every alert. Write it so a computed figure (a sum, an average) added to a signature later fails this test.
- One AppTest per app (reuse the helpers of the existing page tests without editing them): after the demo loads, the number of gl-signature blocks equals the number of alert cards and the refs show as chips.
You may edit an existing test only where it pins the old inline-code refs after Source refs:; list each one you change.

Change nothing else: no change to the guard, the detectors, the replay, the README or the Home page. Environment: Windows. You cannot run commands; the hooks lint each file you write and run the tests when you stop. When done, list the files you changed.
