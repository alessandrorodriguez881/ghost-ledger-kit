Session 32: every citation a person reads must point to the line they see when they open the file. The owner approved this on 17 Nov.

The problem. For CSV files, source_row is the 0-based index of the data row. So the GYMPLUS card of Zombie Subscriptions shows the chip zombie_demo_statement.csv · row 181, but a judge who opens data/samples/zombie_demo_statement.csv in a text editor or a spreadsheet finds that GYMPLUS charge on line 183 (line 1 is the header), and line 181 is a different charge. In a kit whose promise is that every figure cites its row, a citation that points to the wrong line looks like an invented one.

The internal key stays exactly as it is. Do not change: source_row, source_ref, Alert.id, the source_refs and data of any alert, any detector, the number guard, the columns sent to the model (_LLM_ROW_COLUMNS and _NEVER_SENT_COLUMNS in ledger_kit/explainer.py), ledger_kit/replay.py, any file in data/live_runs, the pinned sets in tests/test_recorded_verdicts.py, docs/benchmark.md (generated and checked byte for byte), the number of folders in .kiro/specs (18) and of files in .kiro/steering (6). The recorded real answers and the alert ids depend on them. If a test shows that one of these would change, stop and say so instead of changing it.

What to build. Write the requirements first, then the code and the tests:
- in .kiro/specs/ledger-core: a new last section with requirements REQ-LN-01 onwards for the source line, and its tasks at the end of tasks.md;
- in .kiro/specs/app-signatures: REQ-AS-25 onwards for what the person sees, and its tasks.

1. Models. In ledger_kit/models.py, Transaction, Invoice and Supplier get source_line: int | None = None, the 1-based line of the file where the record starts, with the header as line 1, exactly as a text editor numbers lines and as a spreadsheet numbers rows when no cell spans two lines.
2. Readers. Every CSV reader that sets source_row (ledger_kit/ingestion/csv_reader.py, invoice_reader.py, supplier_reader.py and any other) sets source_line for every record it returns. Blank lines between records and quoted cells that span several lines must still give the line where the record starts. Norma 43 sets it to the line of the record 22, which is its source_row today. Facturae leaves it None: an XML invoice has a position, not a line. Every quarantine record of every reader gets a source_line key too: the line where the bad record starts, or None for a record about the whole file or an XML invoice. Keep all the other keys as they are.
3. Ledger frames. ledger_kit/ingestion/normaliser.py adds source_line right after source_ref in CANONICAL_COLUMNS, INVOICE_COLUMNS and SUPPLIER_COLUMNS, as a nullable integer (pandas Int64), so None stays empty. No detector and no alert reads it, and it is never sent to the model.
4. Chips. In ledger_kit/ui/signatures.py, refs_chips_html takes an optional map from source_ref to source_line, and a small helper builds that map from any frame that has both columns (a frame without source_line gives an empty map). A ref with a known line shows file · line N. A ref of an .xml file with no line shows file · invoice N, N being its 1-based position. Any other ref shows the raw source_ref, never the word row next to the internal number. The title attribute keeps the raw source_ref, and when the line is known it adds that it is line N of the file. Every chip the person sees gets the map: the alert cards of the three apps, the Home tiles (apps/home_tiles.py, tile_refs_html) and any other caller of refs_chips_html. The line and N more cited rows on a tile is a count, so it stays.
5. Tables. Wherever a table or list shows a source_ref to the person, the line is next to it: the Source rows expanders (DISPLAY_COLUMNS in ledger_kit/ui/reference_app.py gets source_line right after source_ref), the list of refs of the Zombie Subscriptions tombstones (_refs_markdown), and the lantern of Phantom Invoices (lantern_view, REQ-AS-23 gets source_line right after source_ref; for an XML invoice the cell is empty). The two quarantine tables (ledger_kit/ui/reference_app.py and apps/phantom_invoices/settings.py) rename their column row to line and fill it from source_line; empty when there is no line.
6. Docs. Update the source_row line of the Transaction model in .kiro/steering/tech.md and the source_ref line in .kiro/steering/testing.md so they also describe source_line. If README.md or a file in docs/ shows a chip with the word row and a number, change it to line with the right number.
