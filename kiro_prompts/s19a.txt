Session 19a. A separate Kiro Crew app (Night Watch, in its own repository, for the Best Kiro Crew App prize) will watch a folder and check every new statement or invoice with this kit. It must not install the kit into Crew's own Python (the pinned pandas and streamlit could clash), so it will call the kit as a command run with the kit's own Python. Add that command, the Kiro way: a small NEW spec .kiro/specs/scan-command/ (requirements EARS with REQ-SC ids... use REQ-SCAN ids to avoid the showcase prefix, acceptance examples, design, test-first tasks), then implement it in this same call and tick the tasks.
1. scripts/ledger_scan.py with two subcommands, standard library argparse, deterministic, no language model, no network:
- scan FILE [FILE ...] [--suppliers CSV] [--payments FILE] [--as-of YYYY-MM-DD]: sniff each file by content with the existing sniffer; bank statements (CSV or Norma 43) go through the Zombie Subscriptions pipeline (with empty aliases and cancellation dates, so detectors that need them simply do not fire) and the Vampire Fees pipeline; invoices (CSV, JSON or Facturae XML) go through the Phantom Invoices pipeline with the optional supplier master and payments. Each app's own run_pipeline is used, exactly as its page runs it, CPI context included for Zombie. Print one JSON object to stdout: kit version; per file its path, sha256, detected kind, row count and quarantined count; and every alert with alert_id, app, detector, severity, title, the fixed template text of the card (the same text the card shows without a model), source_refs, the cited rows with the visible columns only, and the Exorcise drafts in en and es when the alert type has a template (else null). A file that cannot be read is reported in the JSON with its error, the others still run; the exit code is 0 when the command ran, 2 for bad arguments.
- check --alert-id ID --text TEXT FILE [FILE ...] [same options]: rerun the scan, find the alert and apply the number guard of ledger_kit.explainer to TEXT for that alert and its cited rows; print {passed, rejected tokens}; an unknown alert id gives passed false and an error message.
2. The JSON must be stable: keys in a fixed order, alerts ordered by severity then title, money as strings exactly as the kit formats them, dates in ISO form. The same files give byte-identical output.
